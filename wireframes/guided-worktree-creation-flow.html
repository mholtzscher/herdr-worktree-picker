Guided worktree creation

Review question: Does the replacement flow make intent, branch identity, recovery, and exceptional states explicit enough to implement without returning to the single-screen shortcut model?

Flow topology

Start · Choose outcomeDefault: Open an existing branch. Esc closes.
↓
A · New from current HEADBlank name → validate exact input → resolve HEAD on submit.
B · Open existing branchSearch local/remote → Enter opens immediately.
C · New from another baseSearch base → blank name → resolve ref on submit.
Inline name errorInvalid or existing local names remain on the name screen.
Remote-name conflictChoose a different local name or return. Never open unrelated local work.
Fetch/create failureReturn to the originating screen with its state retained.
↓
Creating → verify tracking → notify → closeTracking repair failure is partial success: warn and close without retry.

Inspectable popup states

Use the scenarios, click rows, type in fields, or exercise Enter, Esc, arrows, Ctrl-R, and Ctrl-U.

Decision notes

  • Public action becomes herdr-worktree-picker.create.
  • Each path remembers its own query, selected ref, and name draft until close.
  • Search is case-insensitive substring matching; name input is never derived from search.
  • Checked-out refs are disabled for opening but remain valid bases; paths are absolute.
  • The current branch is excluded from “another base.” Detached HEAD disables only Path A.
  • Refs resolve on submission. Remote-derived locals track the exact selected remote.
  • Ctrl-R is asynchronous and global; stale refs remain usable after fetch failure.
  • Creation cannot be cancelled. Ordinary failure returns to its source; partial tracking failure warns and closes.
  • The terminal implementation deliberately supports append, Backspace, and Ctrl-U, not movable-cursor editing.

Implementation contract at a glance

Stable purposeIntent chooses. Search searches. Name names. Enter accepts the visible choice or field.
Safe identityRemote refs never silently resolve to unrelated same-named local branches.
One-step BackEsc returns one screen and preserves path-local state; Esc closes only at Start or fatal error.
Actionable selectionInitial selection and arrows skip disabled rows and clamp at list ends.
Responsive workFetch remains navigable; creation is exclusive, visible, and non-cancellable.
CompletionSuccess focuses, verifies tracking, notifies best-effort, and closes without a success screen.
