Guided worktree creation + GitHub PRs

Review question: Can a keyboard-first user discover an open GitHub PR, optionally filter it, and press Enter once to create a fresh, focused review worktree—while keeping loading, refresh, and failure recovery understandable?

Inspectable popup states

Use scenarios, click rows, type a filter, or use Enter, Esc, arrows, Ctrl-R, and Ctrl-U.

What this extension decides

  • Open a GitHub PR appears immediately after existing branches, and the direct action shares the same screen/state.
  • PR rows are intentionally compact: title first; author, fork head, and date second.
  • Loading starts after the popup opens. Refresh never blocks searching an existing list.
  • Selection follows a PR number across filtering and refresh whenever it remains visible.
  • Enter never accepts a typed number/URL—only a selected filtered row.
  • Preparation is brief, non-cancellable, and verifies the fetched immutable commit before creation.
  • Every retry allocates a fresh pr/<n>-… branch; earlier copies are untouched.

Implementation contract at a glance

Two entry routesIntent Esc returns to the intent menu. Direct-action Esc closes the popup.
Bounded discoveryOne updated-first request shows at most 1,000 open PRs and labels a real cap.
Safe fork supportFetch only the base repository’s pull ref; never add a contributor remote.
Exact snapshotFetch then revalidate; a moving head gets one retry before a clear race error.
Local filteringCase-insensitive matching spans number, title, author, and head owner/branch.
Explicit lifecycleGenerated review branches have no upstream; cleanup stays manual and out of scope.
